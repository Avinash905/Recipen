# Recipen empty and error state review

Reviewed November 14–15, 2026. This is a review, not an implementation pass. Evidence is labeled **Observed** for local Chrome checks against the synthetic database and **Code** for source inspection. A local server outage was simulated by stopping the test backend only. No live data or external service was changed.

## Findings

1. **High · Observed · Out-of-range pages strand users.** Public results and Admin Users can display “Page 99 of 1”; Previous moves back only one page at a time. The public message says to check back for new additions even though results exist. **Fix:** Move to the last valid page, or offer a direct return to the first page. (`client/src/components/cards/AllCards.jsx:67`, `client/src/pages/dashboard/Users.jsx:138`)
2. **High · Observed · A failed catalog request also says “0 recipes.”** When the backend was stopped, the count and error appeared together, incorrectly suggesting an empty collection. **Fix:** Hide the count until a request succeeds and show only the failure and retry action. (`client/src/components/cards/AllCards.jsx:60`)
3. **Medium · Observed · Long search terms overflow on a 320 px screen.** The unbroken term extends beyond the no-results panel and causes horizontal scrolling. **Fix:** Wrap or safely truncate the displayed term and keep the full value in the search field. (`client/src/components/cards/AllCards.jsx:67`)
4. **Medium · Observed · Story form errors remain after the affected text changes.** After correcting blank content, the old content error stayed until another submit; the missing-image message also persisted after clearing the form. **Fix:** Clear or update the relevant error when its field changes. (`client/src/pages/blogs/AddBlog.jsx:33`, `client/src/pages/blogs/AddBlog.jsx:45`)
5. **Medium · Observed · Missing editor items look like a temporary failure.** An invalid story edit address showed “Could not load this item” and only Try again, despite a not-found response. The recipe editor has the same branch in code. **Fix:** Distinguish missing items from network failures and link back to the relevant library. (`client/src/pages/blogs/EditBlog.jsx:97`, `client/src/pages/recipe/EditRecipe.jsx:147`)
6. **Medium · Observed · Comment-post failure relies on a temporary toast.** During a backend outage, the comment text was preserved, but the failure message disappeared and there was no persistent explanation beside the form. **Fix:** Keep a visible inline error and retry guidance until the user edits or successfully submits. (`client/src/pages/blogs/SingleBlog.jsx:60`, `client/src/pages/recipe/SingleRecipe.jsx:117`)
7. **Medium · Observed and code · Comment list content is replaced by an error after a failed post.** In the outage test, the comment list switched to a retry message. A failed mutation invalidates the comment query, and the list prioritizes the error over existing data. **Fix:** Avoid invalidating after failed writes and preserve previously loaded comments with a clear warning. (`client/src/components/comment/CommentList.jsx:19`, `client/src/features/blog/blogApiSlice.js`)
8. **Medium · Code · Sign-up and profile submission failures use transient notifications.** Unlike sign-in, there is no persistent form-level error, so users can miss why a request failed. **Fix:** Keep the error near the form and preserve entered values until it is resolved. (`client/src/pages/auth/SignUp.jsx:27`, `client/src/pages/profile/Profile.jsx:48`)
9. **Medium · Observed and code · Story titles have an unexplained five-character rule.** “Tea” was blocked with the browser’s generic format message; the server only requires non-empty text. The inline sentence is grammatically incomplete. **Fix:** Align client and server rules and show the requirement clearly before submission. (`client/src/pages/blogs/AddBlog.jsx:101`, `server/controllers/blogController.js`)
10. **Medium · Code · Sign-up name and password guidance does not fully match browser validation.** The name input states a 2–100 character rule but does not enforce it locally; the password’s 72-byte limit is enforced by the server, not the field pattern. **Fix:** Validate the same rules before submission and attach persistent, plain-language errors to the fields. (`client/src/pages/auth/SignUp.jsx:72`, `server/utils/accountValidation.js`)
11. **Medium · Code · Session restoration has no explicit network-failure state.** A refresh failure other than 401 or 403 clears the loading state without explaining that the service is unavailable. **Fix:** Show a recoverable connection message and a retry option without presenting a network failure as an account problem. (`client/src/features/auth/PersistLogin.jsx:13`)
12. **Low · Observed · Admin search empty states lack useful guidance.** Desktop shows the grid default “No rows,” while compact cards say “No matching results”; neither gives a clear reset action. **Fix:** Use the same contextual no-match message and clear-search action at every size. (`client/src/pages/dashboard/Users.jsx:136`, `client/src/components/dashboard/Table.jsx`)
13. **Low · Observed · Search empty states duplicate recovery actions.** A search with no matches shows Clear in the input and two Clear filters actions. **Fix:** Keep a clear action near the search and one contextual action in the empty panel. (`client/src/components/cards/AllCards.jsx:48`, `client/src/components/cards/AllCards.jsx:58`)
14. **Low · Observed · Guests sent to sign in from Saved recipes are not told why.** The destination is preserved, but the sign-in screen only says “Welcome back.” **Fix:** Explain that signing in is needed to open saved recipes and retain the return path. (`client/src/features/auth/RequireAuth.jsx:24`, `client/src/pages/auth/SignIn.jsx`)
15. **Low · Observed and code · Homepage error and empty copy says “blogs” while navigation says “stories.”** The outage exposed “Could not load blogs”; the empty path uses the same wording. **Fix:** Use the visible label “stories” consistently. (`client/src/components/homeCategories/HomeCategories.jsx:20`)
16. **Medium · Code · Image upload errors are temporary and file-size validation is absent.** Invalid formats and failed uploads produce toasts; the helper checks type but not file size before upload. **Fix:** Show a persistent message next to the picker and validate an agreed size limit. Actual service uploads were not tested. (`client/src/common/uploadImage.js:4`)

## What worked in the checked cases

- No-match recipe and story searches show the query and offer a way to clear filters.
- Empty saved recipes and empty creator libraries explain the state and link to the next action.
- Invalid recipe and page URLs show understandable not-found messages and navigation back.
- A wrong password produces a persistent, non-specific sign-in error.
- A failed comment did not erase its text; comment loading and Admin loading each offered retry.
- Homepage recipe and story sections successfully reloaded after the local server restarted and their retry buttons were used.
- Blank story content and a missing story image received explicit messages and focus moved to the relevant control.

## Coverage and limits

Browser checks covered public search, long search on a small viewport, out-of-range public and Admin pages, empty saved and creator collections, incorrect sign-in, missing editor and recipe links, empty story comments, story-form validation, a failed comment, and public/Admin loading errors. Source inspection covered associated empty/error branches for recipes, stories, sign-in, sign-up, profile, uploads, comments, dashboard and session restoration.

The browser stopped responding during an attempted offline sign-up check, so sign-up network failure was assessed from code rather than observed. We did not test actual image uploads, contact delivery, payment, every mutation failure, screen-reader operation, or live production behavior. We did not change application code or fix findings in this review.

## Fix follow-up, November 15, 2026

The 16 findings above were addressed in the local code. Pagination returns to a valid page; errors no longer claim there are zero results; long searches wrap; creator and account errors persist or clear when corrected; missing editor items link back; failed comment writes preserve loaded comments and text; registration validation matches the server's name and password limits; session restoration offers retry; Admin empty results offer clear search; guest saved-recipes access explains sign-in; homepage copy says stories; and image pickers show persistent errors and reject files over 5 MB. Short story titles now follow the server's nonblank rule.

Browser checks covered public and Admin pagination, Admin empty search, missing story editor, short story title and corrected content, registration name and password limits, offline registration and profile saves, a failed and successful comment, restoration after a local outage, mobile long search, and a synthetic oversized image. The oversized file was rejected before upload; actual image service upload success and failures, all other individual mutation failures, full screen-reader coverage and deployed behavior remain unverified. Automated client build, lint and account-state checks and local catalog, comment, ownership and saved-recipe tests passed. The changes are local and uncommitted.
