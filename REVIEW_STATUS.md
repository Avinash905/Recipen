# Recipen review status

The application changes and tests are local and uncommitted. Nothing has been deployed. The historical audit is not fully closed.

- Public, saved and author collections use paginated server queries with search, filtering and sorting. The legacy catalog API is retained for compatibility. In a local synthetic 1,200-recipe test, the warm median first-page request fell from 27.4 ms to 2.7 ms after deferring author lookups until after pagination. Production-sized performance is unmeasured.
- A later local synthetic benchmark with 1,200 added recipes and 10 concurrent clients measured a 4.2 ms median and 8.1 ms 95th percentile over 100 first-page requests. This is a local API measurement, not a production or full-page performance test. The benchmark's earlier “author search” label actually referred to title search and has been corrected.
- New per-device sessions store hashed refresh tokens and rotate them on refresh. Sign-out and account-switching safeguards have been added, including changes intended to address the two server timing cases; those cases still need independent validation, as described in `PENDING.md`. Browser authentication requires Web Locks. Old refresh cookies require sign-in again.
- Frontend lint and production build pass. The main and admin-grid bundles are split, and no chunk exceeds the build warning threshold; load times have not been benchmarked.
- Synthetic integration checks cover account access, ownership, paginated collections, session rotation, ratings, favorites and profile changes. Catalog, saved-recipe, rating and profile checks passed again locally on November 14, 2026. Earlier browser checks covered selected journeys but do not establish that the current session changes are safe across tabs.
- Safari could not be inspected due to a screen-capture error. Firefox and Edge were unavailable. Physical-device, screen-reader, upload and production performance testing remains open.
- On November 14, 2026, Chrome successfully signed in with a local synthetic Pro account, restored the account after a reload, and signed out. Safari could not be tested because the computer-use capture failed; Firefox and Edge were not installed. Dia was installed but not tested. This is a basic browser check, not a cross-browser sign-off.
- On November 14, 2026, a local browser accessibility-tree and keyboard spot check confirmed that the home skip link moves focus to search, ingredient checkboxes toggle with Space, the share menu closes with Escape and returns focus, and sign-in inputs and password visibility have accessible labels. This was not a screen-reader test or a full accessibility audit.
- A later local creator check confirmed that Enter opens the recipe and story editors from their owner action menus. Editor image instructions now distinguish an existing image from a missing required image. The admin Users, Recipes and Stories screens loaded with synthetic data; opening and cancelling the account-disable confirmation left the account active. Synthetic blog ownership, comments, admin deletion and disabled-account checks passed.
- A subsequent local pass added persistent sign-in errors, single-focus share-menu actions and direct Edit links in the creator lists. A synthetic browser check confirmed incorrect and successful sign-in, keyboard focus in the share menu, and Edit links on both creator lists; social sharing destinations were not opened. The homepage now requests catalog summaries rather than full list records.
- Public pages now render while session restoration is pending, while protected pages continue to wait. Comment and favorite mutations use narrower cache invalidation. Account responses now provide profile information separately from the shorter access token. Account data revisions prevent an older response from replacing a newer snapshot in client state; an isolated state test and a basic browser save/reload check passed. Coordinated client/server rollout and broader concurrency verification remain open.
- Recipe and story comments now load in pages. Synthetic API checks covered both types, and a local browser check covered recipe comment navigation, adding and deletion. Sign-in has an additional per-account failure limit, tested in isolation; its production limitations are recorded in `PENDING.md`.
- On November 14, 2026, dependency updates cleared the npm advisory reports for both projects. Clean installs and synthetic account, creator, catalog, comment, favorites and session tests passed on Node 24. Browser checks covered sign-out, sign-in, recipe navigation, creator library access, and item-specific recipe and story titles. Major dependency upgrades and remaining compatibility checks are recorded in `PENDING.md`.
- Node 26.13.1 is installed and selected for the project with `.nvmrc`. Clean installs, build, lint, account state, session, creator, catalog, favorites and comment checks passed with synthetic data. The current local visual pass checked home, recipe discovery and detail, profile, recipe creation, and the three mobile admin lists. It found inconsistent mobile admin search layouts, which were aligned. This is not a complete visual or cross-browser review.
- The same pass inspected desktop story listing and detail and the contact screen. Duplicate unavailable-contact wording was removed. A Node 26 synthetic API benchmark with 1,200 temporary recipes measured 2.4 ms median for the first page and 3.6 ms median with ten concurrent clients; this is not a full-page or production performance measurement.
- Recipe cards now request a rating count and average instead of the full rating list. The original catalog response remains available to older callers. Synthetic tests checked both response formats and the browser displayed the expected rating.
- A synthetic Basic account could open its saved collection and received an access explanation for the creator page. That page now has its own browser title. Sign-up password requirements are visible on small screens and associated with the input; the same guidance appears when changing a password. Safari capture still failed when retried.
- Server startup now disconnects and exits with a failure status when database connection or index setup fails. A local invalid-database configuration confirmed the failure exit; an actual index-creation failure has not been simulated.
- A further local visual pass covered story creation and editing, the creator libraries, and recipe editing at 320 px. Story labels are consistent across navigation and editors, the new-story preview uses the published story formatting, and clearing edits now clears the stale unsaved-draft message. The back-to-top control is keyboard accessible on desktop and hidden on phones, where it previously covered recipe actions. It also honors reduced-motion preferences.
- Admin users, recipes and stories use compact cards below 1280 px so status and moderation actions are visible without horizontal scrolling. Browser checks covered users and recipe moderation at 768 px, story moderation at 1024 px, and the users table at 1440 px. The account-disable confirmation was opened and cancelled with synthetic data.
- Invalid recipe and story addresses now return a not-found response instead of a server error. Synthetic API tests and browser checks confirmed the appropriate missing-item messages. Story error messages and delete confirmations use the same terminology as the rest of the interface.
- Checkout is paused. Contact delivery, policy content, verified email changes and service decisions remain in `PENDING.md`.
- Rotate exposed active secrets and audit existing email data before any deployment. See `server/local-test/README.md`.

## Visual polish pass, November 15, 2026

- Reviewed the local app with synthetic data, including the home page, catalog and detail screens, account screens, creator editors and libraries, contact, not-found, and admin views. A browser measurement checked 20 routes at 320, 768 and 1440 pixels with no document-wide horizontal overflow. This measurement does not establish that every element or state is visually perfect.

- Aligned creator and comment actions with the existing button style, made secondary editor actions distinct, styled destructive dashboard actions, and added a visible current-section indicator in the dashboard. Refined the scrollbar, catalog author and missing-image text contrast, comment fields, rating contrast, and duplicate search-clear controls.
- Replaced the remote sign-in and registration background with the existing bundled image after the remote image failed to appear during the review. Browser checks confirmed the bundled image and sampled updated controls.
- Form-label inspection on 13 representative routes found no visible input, textarea or select without a label. Mobile navigation opened and Escape returned focus to its trigger. These are targeted checks, not a full assistive-technology audit. Browser screenshots were sampled, not captured for every state at every width.
- Remaining release checks include end-to-end main journeys, real-content review and live-site testing after deployment. Screen-reader and physical-device checks have not been performed. External integrations remain deferred as requested.
